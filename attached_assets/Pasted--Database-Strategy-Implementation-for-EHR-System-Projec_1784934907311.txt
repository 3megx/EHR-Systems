# Database Strategy & Implementation for EHR System

**Project**: Electronic Health Records (EHR) Platform  
**Backend**: ASP.NET Core Microservices (from previous prompts)  
**Goal**: Design and implement a **polyglot, high-performance, HIPAA-compliant** database architecture that supports complex clinical data, high concurrency, search, analytics, and caching.

## 1. Overall Database Strategy (Polyglot Persistence)

Choose the right tool for the right job:

- **PostgreSQL** (Primary OLTP Database) — Default for most services.
  - Strong ACID compliance, complex relationships, JSONB support.
  - Use for: Patient demographics, clinical notes (with JSONB), appointments, prescriptions, billing.

- **MongoDB** (Document Store) — When flexible schema or large unstructured data is needed.
  - Use for: Clinical documents, progress notes, scanned PDFs metadata, device-generated data (vitals streams), audit logs with high volume.

- **MySQL** (When Needed) — For services requiring strict relational consistency or legacy integration.
  - Use cases: Billing/Claims (if integrating with specific insurance systems), simple reporting DB.

- **Redis** — Caching, sessions, rate limiting, real-time counters.
  - Use for: Patient lookup cache, frequently accessed records, session management, pub/sub for cache invalidation.

- **Elasticsearch** — Full-text search, logging, analytics search.
  - Use for: Global patient search, clinical note search, medication interaction search, audit log search.

- **Snowflake** (Analytical Warehouse) — Denormalized data for reporting and population health analytics.

## 2. Detailed Implementation Requirements

### PostgreSQL (Main DB)
- EF Core as primary ORM (80% of operations).
- Dapper for complex queries, reports, bulk inserts/updates.
- JSONB columns for flexible clinical data.
- Proper indexing strategy (including GIN for JSONB).
- Row Level Security (RLS) + policies for multi-tenant / HIPAA.
- Temporal tables or audit triggers for history.
- Connection resiliency, retry policies.

### MongoDB
- Official MongoDB .NET Driver.
- Use when schema evolves frequently or for large binary/document storage.
- Repository pattern abstraction.
- Indexing strategy for common queries.
- Change Streams for real-time updates where needed.

### Redis
- StackExchange.Redis or Redis OM.
- Cache-Aside pattern with proper invalidation (on domain events).
- Distributed locking when necessary.
- Session store.
- Pub/Sub for cross-service cache invalidation.

### Elasticsearch
- NEST / Elastic.Clients.Elasticsearch client.
- Index per service or shared indexes (patients, clinical).
- Automatic indexing on data changes (via Kafka consumers or Outbox).
- Powerful search queries (fuzzy, autocomplete, vector search for future AI).
- Kibana for visualization and audit log exploration.

### Cross-Cutting DB Concerns
- **Unit of Work** — Across EF Core (PostgreSQL/MySQL) with transaction support.
- **Generic Repository** — Abstracted per DB technology where needed.
- **Audit Logging** — Centralized or per-service with immutable records (who, what, when, IP, reason).
- **Data Encryption** — Column-level encryption for PHI (Protected Health Information).
- **Backup & Recovery** — Automated strategies.
- **Multi-Tenancy** — Support for hospital/clinic level isolation (separate schema or DB per tenant where required).
- **CDC** — Change Data Capture to push changes to Snowflake + Elasticsearch.

## 3. Implementation Guidelines for Agent

For each microservice:
1. Configure connection strings in appsettings (with environment overrides).
2. Implement DbContext (for relational) or MongoClient with proper configuration.
3. Create repositories with both EF Core and Dapper methods.
4. Add caching layer (Redis) with decorators or Cache-Aside.
5. Set up Elasticsearch indexing services/consumers.
6. Write database migration strategy (EF migrations for Postgres/MySQL, MongoDB schema versioning).
7. Include health checks for all databases.
8. Add test containers for integration tests.

**Security & Compliance**:
- Always encrypt PHI.
- Audit every read/write of sensitive data.
- Implement consent management.
- Data minimization and retention policies.

**Performance**:
- Query optimization, indexing, pagination everywhere.
- Caching hot paths.
- Read replicas where possible.
